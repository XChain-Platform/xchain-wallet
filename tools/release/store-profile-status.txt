IMPLEMENTED store-profile-build-lane

# Whether the `store` build profile EXISTS as a build mechanism.
#
# It does, so a `store` artifact may be signed.
#
# What the label means today: the profile exists and is verifiable, and the
# `HIDDEN_SURFACES` registry in `packages/web/src/surfaces/registry.js` is
# EMPTY for both profiles. The 2026-10-09 review decision ships every product
# surface in every profile, so a `store` bundle carries the same product as a
# `default` one. It differs in CSP, sourcemaps, packaging and its signed
# profile stamp, and it is no longer a reduced product.
#
# What the profile mechanism provides:
#
#   `XCHAIN_BUILD_PROFILE` resolution (a typo throws rather than quietly
#   building `default`), a profile-aware and strictly SUBTRACTIVE CSP, a
#   `build-profile.txt` stamp plus a meta tag emitted into the dist, a mobile
#   staging step that refuses anything but a `store` bundle, and
#   `sourcemap: BUILD_PROFILE !== 'store'` in `packages/web/vite.config.js`.
#
# What stays available but is currently unused: the compile-out mechanism. If
# a surface is ever listed in `HIDDEN_SURFACES`, vite swaps
# `surfaces/<name>.jsx` for a twin that imports nothing, and the
# `xchain-hidden-surface-guard` plugin (enforce 'pre') fails the build if a
# `SURFACE_MODULES` entry is imported from anywhere else. With the registry
# empty no swap happens and the guard has nothing to protect.
#
# Evidence, all of it rerunnable: `test/smoke/audits/release-build-profiles.smoke.js`
# pins that the store profile hides no product surface and pins the store
# build's sourcemap setting; `test/unit/mobile/storeSurfaces.test.js` and
# `test/unit/mobile/storeProfileBuild.test.js` tie the registry to the surface
# modules and routes.
#
# The gate above stays live and still fails shut on anything but a line
# beginning IMPLEMENTED. Read it as: the profile mechanism is in place. It does
# NOT say any surface is absent from a store build. A verifier reading `store`
# in a signed, append-only manifest must consult `HIDDEN_SURFACES` at the
# signed commit for that. If the profile mechanism is ever removed or
# bypassed, put this line back to UNIMPLEMENTED in the same commit. If a
# surface is later added to `HIDDEN_SURFACES.store`, update this prose in that
# same commit.
