Notes on the runs:

- The Android probe APK's `MainActivity` carries the same `HttpURLConnection` POST and `Intent.ACTION_VIEW` calls as `tmp/P4ScratchPlugin.java`, adding only timeouts, the response read and log lines. The emulator build differs from the hardware build only in its target (`10.0.2.2` in place of `127.0.0.1` behind `adb reverse`) and its payload and URL labels.
- The Android open was pinned to the scratch capture package, so no browser was started on the emulator. The iOS open went to the simulator's system handler; SpringBoard accepted it and `open` returned `true`.
- The iOS app needed a `UIApplicationSceneManifest`: without one, iOS 27.2 refused the launch with "UIScene life cycle is required". The app also sets `NSAllowsLocalNetworking` so the cleartext loopback POST is allowed; the shipped plugin targets HTTPS only.
- The AVD ran with `-read-only -no-snapshot`, so the shared AVD was not modified. The emulator and the simulator were stopped after the runs.

The scratch sources, APKs, app bundle and logs live under `tmp/` (`tmp/p4/` for the earlier rounds, `tmp/p4-claude/` for the emulator and simulator runs).

### Platform source checks

The scratch Swift source uses `URLSession.shared.data(for:)` for the POST and `UIApplication.shared.open` for the external open. It typechecked against the iPhone Simulator 27.2 SDK and ran unchanged in the simulator app above.

The scratch Java source uses `HttpURLConnection` for the POST and `Intent.ACTION_VIEW` for the external open. It compiled against Android API 36. The scratch APKs were signed and verified with `apksigner` before each run.

### Draft wire-audit result

The isolated draft adds a third `host: '*'` entry for a site-selected callback destination with these properties:

- party: third party
- shells: desktop and mobile
- carries: requesting IP plus the approved or rejected result, including any signed payload
- control: user initiated, destination shown before approval, and no delivery before Approve or Reject
- source: native site-request callback sender

A mechanical copy of `test/unit/mobile/wireAudit.test.js` changes only import paths and its repository-root anchor so it can load the draft module while retaining all 23 assertions. Both were rerun on 2026-11-22 with the same result.

Direct inspection of the loaded draft found three wildcard entries, exactly one callback entry, and this de-duplicated mobile host disclosure:

```text
*, api.coingecko.com, arweave.net, downloads.xchain.io,
```

The third wildcard class is therefore compatible with the current mobile audit. It does not by itself validate eventual store-form or privacy-document wording.

### Tor finding

`git grep` found zero `Tor`, `torRouting`, or `SOCKS` symbols under `packages/mobile`. The desktop-only path remains at `packages/desktop/main/torRouting.js`. A native mobile callback implemented with `HttpURLConnection` or `URLSession` therefore has no wallet Tor path in the current tree and must be described as a direct mobile connection. This is source evidence, not a packet capture.

### Implementation constraints carried forward

- Both native implementations need an HTTPS-only target, no credentials, a 10 second timeout, a 10 KB response/result bound, no redirects, and the resolved-address private-range refusal supplied by the site-request delivery layer.
- Android external return must use the verified browser-referrer rule from the design, with a generic HTTPS VIEW fallback. The scratch `ACTION_VIEW` runs validate the API and cross-app dispatch, not the eventual referrer selection logic.
- iOS external return should use `UIApplication.shared.open` and the browser-hint policy from the design. The simulator run validates the API and its dispatch to the system, not the browser-hint selection.
- The iOS app must adopt the UIScene life cycle; iOS 27.2 refuses to launch an app without a scene manifest.
- Native callback failures must resolve into the retryable delivery state rather than silently reporting success.
- The callback wildcard row must remain a separate `WIRE_AUDIT` entry even though `egressHostsFor('mobile')` de-duplicates all wildcard classes to one `*` value.
